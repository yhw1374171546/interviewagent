## 核心模块设计

### 1. JD 解析器 (`jd_parser.py`)

**输入**: 非结构化的 JD 文本
**输出**: `JDAnalysis` — 结构化的岗位分析

通过 LLM 提取:
- 岗位基本信息（名称、年限、学历）
- 必须技能 vs 加分技能
- 软技能、领域知识、核心职责
- 推断出的面试考察重点

**核心决策**: 使用 LLM + Structured Output (JSON) 而非正则/NER，因为 JD 格式千变万化，正则根本无法覆盖所有企业的 JD 写法。

### 2. 题目生成器 (`question_gen.py`)

**输入**: `JDAnalysis`
**输出**: `InterviewPlan` — 一套完整的面试题

按权重分配题型:
| 题型 | 权重 | 目标 |
|------|------|------|
| 技术基础 | 35% | 考察核心技术栈的深度理解 |
| 场景设计 | 20% | 考察架构思维和 trade-off |
| 项目深挖 | 20% | 考察实战经验和问题解决 |
| 行为面试 | 15% | 考察沟通和团队协作 |
| 代码实操 | 10% | 考察 hands-on 编码能力 |

**核心决策**: 不是简单的 prompt 生成，而是先做权重量化分配，再让 LLM 对每个题型针对性出题，保证题目的均衡性和 JD 相关性。

### 3. 答案评估器 (`evaluator.py`)

**输入**: 题目 + 回答
**输出**: `EvaluationResult` — 4 维评分 + 追问决策

四维度加权评分:
```
总分 = correctness × 0.35 + depth × 0.25 + structure × 0.20 + relevance × 0.20
```

追问策略决策树:
```
回答质量很差 → 跳过此人不追问
回答很短   → deepen: "能展开说说吗？"
回答有漏洞  → challenge: "如果 XXX 情况会怎样？"
回答很好   → upgrade: 提高难度追问
回答抽象   → example: "能举个具体例子吗？"
回答充分   → move_on: 进入下一题
```

**核心决策**: 追问不是无脑追问，而是根据回答质量做五分类决策，这是面试官的真实工作方式。

### 4. 面试主控 (`interviewer.py`)

**核心**: 一个状态机，管理面试的全部生命周期

```
Interviewer 对外暴露 4 个核心 API:
  start(jd_text)    → 初始化面试
  next_question()   → 获取下一题
  submit_answer(a)  → 提交回答，返回评估 + 追问/下一题
  skip_question()   → 跳过当前题
```

**核心决策**: 状态机和 UI 层完全解耦 — `interviewer.py` 只负责状态流转和逻辑判断，`main.py` 只负责展示。这样后续换 Web UI 无需改动业务逻辑。

### 5. 报告生成器 (`report.py`)

分两步走:
1. **统计计算** — 直接计算分维度均分、总分、等级（无需 LLM，快速且稳定）
2. **LLM 综合分析** — 优劣势总结、改进建议、面试结论（需要 LLM 的语言能力）

**核心决策**: 评分统计用代码算（确定性），文字分析用 LLM 写（创造性），各司其职。
