# 简历项目定稿 — AI 面试模拟 Agent（秋招版）

> 用于简历「项目经历」栏目的可裁剪 bullet。所有数据均可复现：
> `python eval/feature_eval.py` + `python eval/judge_eval.py --mock` + `python benchmark.py`（全离线）。

## 一句话定位

针对目标 JD 的 AI 全真模拟面试系统：混合解析 → 题库出题 → 双引擎评分 → **Agent 自主追问** → RAG 参考答案 + **沙箱代码判题** + 评估报告，全链路 asyncio 异步。

## 技术栈

Python 3.11+ · asyncio · FastAPI · 原生 JS · DeepSeek API · 规则引擎 · 沙箱判题（Python/C++）· LeetCode 题库（193 题）· RAG 检索增强 · LLM-as-judge 评测

## 简历 Bullet（按面试官视角组织）

**项目：AI 面试模拟 Agent（个人全栈项目）**

- **混合架构**：规则引擎（200+ 关键词）覆盖 JD 解析 70-90% 确定性工作，LLM 只处理语义盲区；题库检索出题（**193 题**：93 原创 + 100 LeetCode 精选）——单场 8 题面试仅 6 次 LLM 调用，输入 token 减少 70%。
- **双引擎评分**：关键词匹配（客观确定性）算正确性/相关性，LLM 语义分析算深度/结构；自建 **LLM-as-judge 评测集**（30 样本人工标注），评分 MAE **0.94**、Pearson **0.991**、一致性 std **0.16**；评测驱动修复中文关键词匹配缺陷（无天然分词边界，MAE 1.50→0.94）。
- **追问 Agent 化（混合 Agent）**：追问从固定 5 分类升级为 **FollowUpAgent 自主决策**（结合题目/回答/历史追问自主判断是否追、追什么），状态机管骨架 + Agent 管自由度，三级降级保可靠——**追问贴题率 0%→100%**（30 样本评测）。
- **沙箱代码判题**：AST 白名单 + subprocess 隔离 + 真实测试用例，支持 **Python/C++**（核心代码 + ACM 双模式），LeetCode 式判题结果（AC/WA/TLE/CE/RE + 耗时）——**接入 LeetCode 100 题**，自动从 examples 生成判题用例 **69 道**（链表/树注入 ListNode/TreeNode 类 + 数组↔对象构造/序列化器）；无自动用例的题（类设计/SQL/Shell）降级 **AI 代码评审**，0 用例拒绝执行（杜绝空用例判 AC 假阳性）——判定准确率 **6/6**（补边界用例后 5/6 提升）。
- **RAG 面经**：**519 条面经**（22 内置 + 397 Knowledge 知识库 + 100 LeetCode 官方题解），轻量检索器（关键词 Jaccard + 字符 n-gram，零向量库依赖可平替 ChromaDB），面试报告参考答案**检索增强生成**——参考答案长度 36→**144 字**、信息密度 +174%、**面经库覆盖题库 72.5%**（140/193 题，未覆盖题回退关键词兜底）。
- **记忆与个性化**：跨会话能力画像（每技能均分/强弱项/进步趋势），画像弱项自动注入下一场面试的追问决策，形成「画像驱动的个性化面试」闭环。
- **工程化**：**261 个测试**（核心模块覆盖率 **87%**，CI 门禁 80%）、量化评测三件套全离线可复现、Docker Compose 一键启动、调用级可观测性（token/成本/延迟全链路埋点 + 全局 stats）、模型路由 + asyncio 并行（单次评估 17.6s→**5.4s**）。

## 高频追问预案（对应 interview_qa.md）

- **为什么不全用 LLM 解析 JD？** 规则确定、可解释、零成本、可复现（同样输入同样输出），LLM 有随机性和成本，只补语义盲区。
- **怎么评价自己的评分准不准？** 用 LLM-as-judge 评测集量化（MAE/Pearson/一致性 std），而不是口头说"效果不错"；评测还驱动了真实修复（中文关键词匹配缺陷）。
- **你的 Agent 怎么自主决策？** 混合 Agent：状态机管骨架（出题/收答/评分），FollowUpAgent 管追问自由度——LLM 根据题目/回答/历史追问自主决定是否追问、追什么，三级降级（规则兜底）保证可靠。
- **RAG 怎么做的？** 面经库 + 检索器（关键词+相似度，零向量库依赖），检索增强生成参考答案；接口先行，装 ChromaDB 可平替向量检索。
- **遇到 LLM 抖动怎么办？** 指数退避重试 + 熔断器（三态）+ 三级降级链 + 规则引擎兜底，全程留日志。
- **代码题怎么判？** 不是 LLM 主观评价——AST 安全审计 → subprocess 隔离 → 真实测试用例跑 pass/fail，LeetCode 式结果（AC/WA/TLE/CE/RE + 耗时）。
- **LeetCode 判题用例怎么来的？** 导入器从题目 examples 自动提取 Input/Output + python3 方法签名，按「参数类型 × 返回类型」分派生成用例代码：链表/树参数用 `list_to_linkedlist`/`list_to_tree` 构造对象，返回值用 `linkedlist_to_list`/`tree_to_list` 序列化后与期望输出比对（判题环境注入节点类定义，与 LeetCode 平台隐藏能力对齐）——100 题里 **69 道**自动生成，剩余 SQL/Shell/类设计题走降级。
- **为什么不能自动判的题不硬判？** 判题底线是不给错误答案发奖：0 测试用例时 `0/0` 会被误判「全部通过」（AC 假阳性），所以无用例的题直接拒绝执行，降级为 **AI 代码评审**（LLM 评正确性/复杂度/质量 + 明示"无自动判题用例"），LLM 不可用再降中性分——三档降级全程留痕，比伪造通过可信。
