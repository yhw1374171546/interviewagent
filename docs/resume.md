# 简历项目定稿 — AI 面试模拟 Agent

> 用于简历「项目经历」栏目的可裁剪 bullet，数据均可复现（`benchmark.py` + `eval/judge_eval.py`）。

## 一句话定位

针对目标 JD 的 AI 全真模拟面试系统：输入简历/JD → 混合解析 → 题库出题 → 双引擎评分 + 智能追问 → 评估报告，全链路 asyncio 异步。

## 技术栈

Python 3.11+ · asyncio · FastAPI · 原生 JS · DeepSeek API（OpenAI 兼容）· ChromaDB（三级降级）

## 简历 Bullet（按面试官视角组织）

**项目：AI 面试模拟 Agent（个人全栈项目）**

- 独立设计并实现面试全链路：规则引擎 + LLM 混合解析 JD（规则覆盖 70-90% 确定性工作，LLM 只处理语义模糊部分），题库检索出题（91 题 × 12 方向倒排索引 + 分层配额），**关键词匹配 + LLM 双引擎评分**（关键词算正确性/相关性，LLM 算深度/结构 + 追问决策），智能追问 + 结构化评估报告。
- **评测驱动质量**：自建 LLM-as-judge 评测集（10 题 × 高/中/低三档人工标注），评分 MAE **0.94**、Pearson **0.991**、追问贴题率 **100%**；评测暴露出中文关键词匹配缺陷（无天然分词边界），修复后 MAE 下降 37%。
- **性能优化**：模型路由（flash 处理高频调用 + pro 仅出报告）+ 出题/暖场 `asyncio.gather` 并行，单次评估 17.6s→**5.4s**（3.3 倍）、创建面试 51s→22.1s；单场面试成本仅 **¥0.049**（8 题真实 DeepSeek）。
- **容错与可靠性**：指数退避重试 + 熔断器（三态）+ 三级降级链；LLM SDK 懒加载，无 Key 自动降级 Mock 全流程可跑；`repair_truncated_json` 抢救推理模型被 max_tokens 截断的 JSON。
- **可观测性**：调用级埋点（延迟/token/成本按阶段记录 + 会话快照持久化 + 全局 stats 聚合），"测不到就优化不了"。
- **工程交付**：**192 个测试**（核心模块覆盖率 **86%**，CI 门禁 80%），GitHub Actions CI + ruff 零错误，Docker Compose 一键启动，SSE 流式报告 + 原生 JS 单视图聊天界面。

## 高频追问预案（对应 interview_qa.md）

- **为什么不全用 LLM 解析 JD？** 规则确定、可解释、零成本、可复现；LLM 有随机性和成本，只补语义盲区。
- **怎么评价自己的评分准不准？** 用 LLM-as-judge 评测集量化（MAE/Pearson/一致性 std），而不是口头说"效果不错"。
- **追问怎么做到贴题？** 追问决策来自评估 JSON + 未命中要点生成上下文追问兜底，贴题率 100%。
- **遇到 LLM 抖动怎么办？** 重试（退避+jitter）+ 熔断 + 降级链 + 规则引擎兜底，全程留日志。
