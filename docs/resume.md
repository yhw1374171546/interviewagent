# 简历项目定稿 — AI 面试模拟 Agent（秋招版）

> 用于简历「项目经历」栏目的可裁剪 bullet。所有数据均可复现：
> `python eval/feature_eval.py` + `python eval/judge_eval.py --mock` + `python benchmark.py`（全离线）。

## 一句话定位

针对目标 JD 的 AI 全真模拟面试系统：混合解析 → 题库出题 → 双引擎评分 → **Agent 自主追问** → RAG 参考答案 + **沙箱代码判题** + 评估报告，全链路 asyncio 异步。

## 技术栈

Python 3.11+ · asyncio · FastAPI · 原生 JS · DeepSeek API · 规则引擎 · ReAct Agent + Function Calling · 沙箱判题（Python/C++）· LeetCode 题库（193 题）· RAG 检索增强 · LLM-as-judge 评测 · 混沌测试 · 成本控制

## 简历 Bullet（按面试官视角组织）

**项目：AI 面试模拟 Agent（个人全栈项目）**

- **混合架构**：规则引擎（200+ 关键词）覆盖 JD 解析 70-90% 确定性工作，LLM 只补语义盲区；题库检索出题（**193 题**：93 原创 + 100 LeetCode 精选）——单场 8 题面试仅 6 次 LLM 调用，输入 token 减少 70%。

- **RAG 面经**：**519 条面经**（22 内置 + 397 知识库 + 100 LC 题解），轻量检索器（关键词 + n-gram，零向量库依赖可平替 ChromaDB），参考答案**检索增强生成**——长度 36→**144 字**、信息密度 +174%、面经覆盖题库 **72.5%**。

  - **安全**：Prompt 注入防护（5 类模式中英双语，评估/追问/报告三处 LLM 出口拦截降分）

## 实习经历

**中科院深圳先进技术研究院 · 机器学习算法实习生 · 2026**

**项目：基于语音信号与对抗学习的阿尔茨海默病早期检测系统**

- **任务与数据**：AD 传统诊断依赖腰椎穿刺/PET，无法大规模筛查；语音低成本，但混杂说话人年龄/性别等混淆信息。在 **ADReSSo 数据集**（166 训练/71 测试，AD/CN 二分类，baseline 0.635）上构建语音病理检测管线；核对训练/测试说话人划分（无重叠、防泄漏），统一预处理管线。
- **多路线基线探索**：冻结 x-vector（512d）/ECAPA-TDNN（192d）嵌入 + MLP 验证语音携带病理信息；实现 resample-based **VTLN** 声道归一化；ECAPA 微调触发**灾难性遗忘**（20.77M 参数 vs 124 样本，Acc 0.463 < random）——为后续设计提供教训。
- **核心创新：GRL 对抗性去混淆**：多任务架构（共享表征 → AD 分类头 + 年龄/性别辅助头）+ **梯度反转层（GRL）** 迫使主干学习"无法区分年龄/性别、但能准确判断 AD"的表征；骨干从 wav2vec2-base（768d）升级到 **distil-whisper（1280d/637M）** 解决"维度不足导致 GRL 破坏主任务"瓶颈；配合 GRL sigmoid 退火、动态 loss 归一化、分层学习率等训练技巧，并对反转系数 λ 做敏感性分析（λ≈0.3-0.5 最优）。
- **验证链**：信号级去说话人化对照（WORLD F0 归一化 + FreeVC，同一 split/seed 控制变量——验证预训练已学得说话人不变表征、F0 归一化无效）；t-SNE 可视化佐证（加 GRL 后表征按年龄聚类消散、AD/CN 仍可分）。
- **结果**：GRL 首次在该任务上 work，Accuracy **0.635→0.803（+26.5%）**、AUC **0.667→0.865**；发现**年龄是主导混淆因素**（GRL-age 0.803 > GRL-gender 0.780 > 纯分类 0.741）；统一 10 轮（seed 0-9）评估（均值±标准差，六指标）、模块化代码全可复现，交付 PROJECT_HANDOVER.md。

## 高频追问预案（口头准备，不进简历）

- **为什么不全用 LLM 解析 JD？** 规则确定、可解释、零成本、可复现（同样输入同样输出），LLM 有随机性和成本，只补语义盲区。
- **怎么评价自己的评分准不准？** LLM-as-judge 评测集量化（MAE/Pearson/一致性 std）而非口头"效果不错"；评测驱动真实修复（中文关键词匹配缺陷）。
- **你的 Agent 怎么自主决策？** 混合 Agent：状态机管骨架，FollowUpAgent 管追问自由度（LLM 结合题目/回答/历史自主决定），三级降级保可靠。
- **RAG 怎么做的？** 面经库 + 轻量检索器（关键词+相似度，零向量库依赖），检索增强生成参考答案；接口先行，可平替 ChromaDB。
- **遇到 LLM 抖动怎么办？** 指数退避重试 + 熔断器 + 三级降级链 + 规则兜底，全程留日志。
- **代码题怎么判？** 不是 LLM 主观评价——AST 安全审计 → subprocess 隔离 → 真实测试用例 pass/fail，LeetCode 式结果（AC/WA/TLE/CE/RE + 耗时）。
- **LeetCode 判题用例怎么来的？** 导入器从 examples 自动提取 Input/Output + 方法签名，按「参数类型 × 返回类型」分派生成：链表/树用 `list_to_linkedlist`/`list_to_tree` 构造、`linkedlist_to_list`/`tree_to_list` 序列化比对——100 题 **69 道**自动生成，其余走降级。
- **为什么不能自动判的题不硬判？** 0 用例时 `0/0` 会误判「全部通过」（AC 假阳性）——无用例直接拒绝执行，降级 AI 代码评审（LLM 评正确性/复杂度/质量 + 明示无用例），LLM 不可用再降中性分，全程留痕。
- **Agent 工具调用怎么证明有效？** 真实评测 8 个多步任务工具选择 100%、成功率 100%（`eval/tool_use_eval.py`）；评测暴露并修复 3 个 mock 测不出的协议 bug（tool_call_id 丢失/消息顺序反/DeepSeek reasoning_content 未回传）——真实 API 冒烟是工具调用类功能的上线门槛。
- **Agent 卡在死循环怎么办？** 循环检测（软上限）：同工具/同参数/同结果重复调用提前终止并给可解释原因，3 次即停（vs 硬上限 20 次）；失败重试是合法行为不计入循环，但连续失败 3 次单独兜底。
- **工具挂了/返回坏数据会怎样？** 混沌测试（FlakyTool 注入瞬时/持续失败/超时/坏数据），真实 5 场景无崩溃率 100%；坏数据场景循环检测兜底，持续失败优雅降级。
- **怎么防面试者操纵评分？** Prompt 注入防护：5 类模式中英双语规则，评估/追问/报告三处 LLM 出口拦截降分，0 API 调用；14 个注入样本全检出、7 个正常回答不误伤。
- **成本怎么控制？** CostBudget 两级熔断：花到 80% 评估自动降级为纯规则（省 LLM 调用），超硬上限强制终止；双上限（成本 + token），默认宽松只兜底异常。
- **上下文太长怎么办？** 评估 prompt 按优先级裁剪（题目/回答 > 历史弱项 > 历史摘要，保留最近轮次），token 预算守卫 0 成本确定性实现。

## 实习经历追问预案

- **GRL 为什么能去混淆？** 梯度反转层让辅助任务（年龄/性别分类）的梯度在反向传播时取反，迫使主干学习"让 AD 分类头保留病理信息、让辅助头无法区分混淆因素"的表征——对抗训练的思想，和 GAN 的判别器-生成器博弈同源。
- **怎么证明提升来自去混淆而不是模型变大？** 对照组：distil-whisper 纯分类（不加 GRL）只有 0.741，加 GRL 后 0.803——同一骨干、同一 split/seed，唯一变量是 GRL，+8pp 归因于去混淆而非骨干。
- **为什么 wav2vec2-base 上 GRL 失效？** 768 维表征容量不足以同时支撑主任务与对抗约束，GRL 会"选择性遗忘"破坏主任务；换 1280 维的 distil-whisper 后表征容量足够，GRL 才首次 work——这是维度瓶颈假设，有 v3-v7 迭代实验佐证。
- **小样本（124 样本）怎么防止过拟合？** 10 轮 seed 独立评估取均值±标准差（不是单次最好结果）；冻结骨干只训头 + 分层学习率；所有结论都有严格对照，杜绝"碰运气"。
- **年龄 vs 性别哪个混淆更严重？** GRL-age 0.803 > GRL-gender 0.780 > 纯分类 0.741——年龄是主导混淆因素（语音衰老特征与病理特征更纠缠），性别影响较小。
- **GRL 系数 λ 怎么定的？** 网格扫描 0.1-0.9，λ≈0.3-0.5 最优——太小去混淆不足、太大对抗梯度压制主任务；配合 sigmoid 退火（前期强对抗、后期放松）稳定收敛。
- **怎么确认没有数据泄漏？** ADReSSo 训练/测试说话人本就不重叠（说话人间划分），我们额外核对了年龄分布，并统一预处理管线，指标可信。
- **t-SNE 看到什么？** 纯分类的表征按年龄聚类（模型在"吃"说话人身份）；加 GRL 后年龄聚类消散、AD/CN 仍可分——从特征空间直接看到去混淆生效，和指标提升互相印证。
