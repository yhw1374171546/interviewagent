# 简历项目定稿 — AI 面试模拟 Agent（秋招版）

> 用于简历「项目经历」栏目的可裁剪 bullet。所有数据均可复现：

## 一句话定位

针对目标 JD 的 AI 全真模拟面试系统：混合解析 → 题库出题 → 双引擎评分 → **Agent 自主追问** → RAG 参考答案 + **沙箱代码判题** + 评估报告，全链路 asyncio 异步。

## 技术栈

Python 3.11+ · asyncio · FastAPI · 原生 JS · DeepSeek API · 规则引擎 · 沙箱判题（Python/C++）· LeetCode 题库（193 题）· RAG 检索增强 · LLM-as-judge 评测

- **追问 Agent 化（混合 Agent）**：状态机管骨架 + **FollowUpAgent 自主决策**（结合题目/回答/历史追问判断是否追、追什么），三级降级保可靠——**追问贴题率 0%→100%**。

- **记忆与个性化**：跨会话能力画像（均分/强弱项/趋势），弱项自动注入下一场追问决策，形成个性化面试闭环。
- **工程化**：**261 个测试**（覆盖率 **87%**）、量化评测三件套全离线可复现、Docker 一键启动、全链路 token/成本/延迟埋点、模型路由 + asyncio 并行（单次评估 17.6s→**5.4s**）。

## 实习经历

**中科院深圳先进技术研究院 · 机器学习算法实习生 · 2026**

**项目：基于语音信号与对抗学习的阿尔茨海默病早期检测系统**

- **对抗性去混淆（核心创新）**：AD 语音含年龄/性别等混淆信息，直接建模会过度依赖非病理特征——设计多任务架构（AD 分类头 + 年龄/性别辅助头）+ **梯度反转层（GRL）** 迫使共享表征"去混淆"；骨干从 wav2vec2-base 升级到 **distil-whisper（637M/1280d）** 解决 GRL 维度瓶颈，配合 sigmoid 退火、动态 loss 归一化等训练技巧——Accuracy **0.635→0.803（+26.5%）**、AUC **0.667→0.865**。
- **结果与发现**：ADReSSo 数据集（166 训练/71 测试，AD/CN 二分类）上 **Acc 0.803 / AUC 0.865**，优于纯分类基线（0.741/0.841）；发现**年龄是主导混淆因素**（GRL-age 0.803 vs GRL-gender 0.780）；ECAPA 小样本微调灾难性遗忘（0.463 < random）、WORLD F0 归一化无效——用可控实验修正研究假设。
- **工程规范**：统一 10 轮（seed 0-9）独立评估（均值±标准差，Acc/F1/AUC/Precision/Recall/Specificity 六指标）、模块化代码（8 实验目录共享 evaluate.py）全可复现，完整交付 PROJECT_HANDOVER.md。

## 高频追问预案（口头准备，不进简历）

- **为什么不全用 LLM 解析 JD？** 规则确定、可解释、零成本、可复现（同样输入同样输出），LLM 有随机性和成本，只补语义盲区。
- **怎么评价自己的评分准不准？** LLM-as-judge 评测集量化（MAE/Pearson/一致性 std）而非口头"效果不错"；评测驱动真实修复（中文关键词匹配缺陷）。
- **你的 Agent 怎么自主决策？** 混合 Agent：状态机管骨架，FollowUpAgent 管追问自由度（LLM 结合题目/回答/历史自主决定），三级降级保可靠。
- **RAG 怎么做的？** 面经库 + 轻量检索器（关键词+相似度，零向量库依赖），检索增强生成参考答案；接口先行，可平替 ChromaDB。
- **遇到 LLM 抖动怎么办？** 指数退避重试 + 熔断器 + 三级降级链 + 规则兜底，全程留日志。
- **代码题怎么判？** 不是 LLM 主观评价——AST 安全审计 → subprocess 隔离 → 真实测试用例 pass/fail，LeetCode 式结果（AC/WA/TLE/CE/RE + 耗时）。
- **LeetCode 判题用例怎么来的？** 导入器从 examples 自动提取 Input/Output + 方法签名，按「参数类型 × 返回类型」分派生成：链表/树用 `list_to_linkedlist`/`list_to_tree` 构造、`linkedlist_to_list`/`tree_to_list` 序列化比对——100 题 **69 道**自动生成，其余走降级。
- **为什么不能自动判的题不硬判？** 0 用例时 `0/0` 会误判「全部通过」（AC 假阳性）——无用例直接拒绝执行，降级 AI 代码评审（LLM 评正确性/复杂度/质量 + 明示无用例），LLM 不可用再降中性分，全程留痕。

## 实习经历追问预案

- **GRL 为什么能去混淆？** 梯度反转层让辅助任务（年龄/性别分类）的梯度在反向传播时取反，迫使主干学习"让 AD 分类头保留病理信息、让辅助头无法区分混淆因素"的表征——对抗训练的思想，和 GAN 的判别器-生成器博弈同源。
- **怎么证明提升来自去混淆而不是模型变大？** 对照组：distil-whisper 纯分类（不加 GRL）只有 0.741，加 GRL 后 0.803——同一骨干、同一 split/seed，唯一变量是 GRL，+8pp 归因于去混淆而非骨干。
- **为什么 wav2vec2-base 上 GRL 失效？** 768 维表征容量不足以同时支撑主任务与对抗约束，GRL 会"选择性遗忘"破坏主任务；换 1280 维的 distil-whisper 后表征容量足够，GRL 才首次 work——这是维度瓶颈假设，有 v3-v7 迭代实验佐证。
- **小样本（124 样本）怎么防止过拟合？** 10 轮 seed 独立评估取均值±标准差（不是单次最好结果）；冻结骨干只训头 + 分层学习率；所有结论都有严格对照，杜绝"碰运气"。
- **年龄 vs 性别哪个混淆更严重？** GRL-age 0.803 > GRL-gender 0.780 > 纯分类 0.741——年龄是主导混淆因素（语音衰老特征与病理特征更纠缠），性别影响较小。
